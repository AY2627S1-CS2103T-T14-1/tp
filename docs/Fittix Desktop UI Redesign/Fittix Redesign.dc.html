02

Layout & information hierarchy

1Header

File / Help menus kept as pills. A filter pill always says whether you are seeing all clients or a find result — so indexes are never ambiguous.

2Client list

Compact cards, index badge first. The selected client's badge turns lime. Each card adds a one-line summary (plan size, next session) instead of the full record.

3Client detail

Profile strip (contact + goal) above the workout plan, grouped Mon→Sun. Exercise tiles carry their plan index; today's row is flagged so the next set is obvious.

4Context column

Three record types, three signals: amber square = diet, violet dot = scheduled sessions (next one filled), lime check = completed history.

5Result history

Replaces the single text box with a scrolling log: echoed command, status icon, one-line message, and usage on error. Newest at the bottom, next to where you type.

6Command bar

Fixed at the bottom, always focused on launch. Border shows state (idle / focused lime / error coral). Usage hints come from the existing MESSAGE_USAGE strings.

Reading orderWho · name, index, goal→What today · flagged plan row→What's next · violet session→Feedback · result log

States via PseudoClass

JavaFX has no :focus-within. Register focused-field and error PseudoClasses and toggle them on the HBox from the TextField's focus listener and CommandBox's existing failure path.

Results as a list

Swap ResultDisplay's TextArea for a ListView of a small record (command, success, feedback, usage). Append on every execute, then scrollTo(size-1). Cap at ~50 items. No model changes.

Derived, not new, data

Day grouping, "next session", "today" and macro bars are computed in the UI layer from existing fields. Load fonts with Font.loadFont at startup; no box-shadows needed (use surface steps).
